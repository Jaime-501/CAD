# T02 — Infraestructura HTTP, errores y reintentos

> Antes de empezar lee: `AGENTS.md`, `tareas/00_REGLAS.md` y `PROGRESO.md`.
> Usa las **firmas reales** registradas en `PROGRESO.md`, no las del plan.
> Ejecuta SOLO esta tarea. Si necesitas tocar un archivo fuera de "Puedes tocar", detente y repórtalo.

**Depende de:** T01

**Objetivo:** Cliente HTTP reutilizable con timeout, cookies, hueco para evasión anti-bot, errores tipados y política de reintentos. (Fusiona T01 y T18 de la v3.)

**Puedes tocar:** `internal/httpx/**`

**NO debes tocar:** `frontend/**`, `app.go`, `internal/models/**`

**Pasos:**
- Definir `HTTPDoer` (`Do(*http.Request) (*http.Response, error)`).
- Crear `NewClient(opts)` con `http.Client` + `cookiejar`. Aislar el `RoundTripper` en una función reemplazable (futuro `utls`).
- Crear `Get(ctx, doer, url, opts)` y `Post(ctx, doer, url, body, opts)` propagando `context.Context`; aplicar User-Agent y Referer opcional.
- Definir `ScraperError` (`Provider`, `Operation`, `URL`, `StatusCode`, `Retryable`, `Cause`) con `Error()` y `Unwrap()`.
- Clasificar: 403 (no reintentable salvo Cloudflare), 404 (definitivo), 419 (recuperable: requiere refrescar sesión; ver T09), 429 (reintentable, respetando `Retry-After`), 5xx (reintentable).
- Definir `ErrCloudflareChallenge`: detectar `cf-mitigated`, cuerpo con "Just a moment" o 403 con esas marcas.
- Implementar `Retry(ctx, policy, fn)`: máximo 3 intentos, backoff exponencial con jitter, respeta `ctx`. **Los POST no se reintentan a ciegas**: solo si el llamador lo declara idempotente.

**Entregable:** paquete `httpx` con `HTTPDoer`, `NewClient`, `Get`, `Post`, `ScraperError`, `ErrCloudflareChallenge`, `Retry`.

**Comprobación:**
- `go vet ./...`, `go test -race ./...` 🔒
- Tests con `httptest.Server`: 200, 404, 419, 429 (con `Retry-After`), 503, y challenge de Cloudflare simulado.
- Las cookies se mantienen entre peticiones consecutivas.
- Test de que `Retry` respeta cancelación de `ctx` y no reintenta POST no idempotente.
