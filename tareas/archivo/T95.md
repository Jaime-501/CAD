# T95 — Arreglar el modo `tactiles` de `verificar_ui.mjs`

## Objetivo

El modo `tactiles` aborta siempre: espera `.btn` en el Home (línea ~7115), pero el Home
sano no renderiza esa primitiva (la actualización es `button.actualizar`; `.btn` solo
aparece en estados de error con «Reintentar»). Corregirlo **sin crear un falso verde**:
el modo debe medir de verdad y fallar si no mide nada.

## Puedes tocar

- `docs/investigacion/ui/verificar_ui.mjs` (solo la rama `modo === 'tactiles'` y, si hace
  falta, una constante auxiliar junto a `MEDIR_TACTILES`).
- `PROGRESO.md` (estado, pendiente «`tactiles` aborta…» → cerrado, desviaciones).

## NO debes tocar

- Código de producto (`frontend/src/**`, `*.go`, `frontend/wailsjs/**`).
- Cualquier otro modo de `verificar_ui.mjs`, `MEDIR_TACTILES` ni `TACTILES_CHICOS`
  (salvo lo indicado arriba).
- `a11y_auditoria.mjs`, datos guardados (historial/favoritos).
- `frontend/package.json.md5`: restáurarlo con `git checkout` si wails lo regenera.

## Pasos

1. Estado inicial: `git status --porcelain` vacío (la ficha ya está commiteada). Si no,
   documéntalo como desviación y sigue.
2. Reproduce el fallo actual: `tactiles` contra `localhost:34115` →
   `Timeout 20000ms` en `waitForSelector('.btn')`. Guarda la salida.
3. En la rama `tactiles`, por cada ancho de `ANCHOS`:
   a. `setViewportSize` + `page.goto(BASE, { waitUntil: 'domcontentloaded' })`.
   b. Espera la carga del Home con
      `page.waitForSelector('.fila .carrusel .tarjeta', { timeout: 60000 }).catch(() => {})`
      (mismo patrón que otros modos, p. ej. línea ~2335). **Nunca** esperar `.btn`.
   c. Mide `MEDIR_TACTILES` en el Home sano (cubre `.chip` y los `.btn` que existan).
4. **Cubrir `.btn` de verdad**: tras la medición del Home sano, intenta forzar el estado de
   error de una fila reemplazando `window.go.main.App.GetHomeSection` por un rechazo
   (como hace `cabecera` con `AddFavorite`, línea ~1138), provoca la recarga con el botón
   `button.actualizar`, espera el «Reintentar» (`.btn`) y vuelve a medir.
   - **Restaura siempre** la función original (`try/finally`), también si falla.
   - Si no se puede forzar de forma estable, **no inventes**: mide solo lo que haya,
     y repórtalo como desviación con la causa.
5. **Anti falso verde**: por cada ancho, imprime cuántos `.btn` y cuántos `.chip` se
   midieron. El modo falla si el **total medido (btn + chip) en un ancho es 0**, y falla
   si no se midió ningún `.btn` en ningún ancho **cuando el forzado de error sí funcionó**.
   Criterios de aprobación sin cambios: `.btn` ≥ 44×44, `.chip` ≥ 40 de alto.
6. Mantén el cierre con `process.exit` (código ≠ 0 si hay fallos) y la tabla
   `| ancho | primitiva | texto | w | h | ok |`.
7. Verifica:
   - Código actual: `tactiles` termina sin abortar, con elementos medidos en los 3 anchos.
   - **Prueba negativa**: simula que no hay nada que medir (p. ej. selector inexistente
     en una copia temporal fuera del repo) y confirma que el modo **falla**.
   - Con T89b (`git checkout 876d14c -- frontend/src`, restaurando después con
     `git checkout HEAD -- frontend/src`): mismo resultado de medición.
   - Revisa el log: **cero** errores de navegador (`ERR_EMPTY_RESPONSE`,
     `reading 'main'`). Si aparecen, repite con el servidor sano; no des por bueno el modo.
   - Comprueba el código de salida real del proceso.
8. Efectos laterales: `git diff --stat` solo debe mostrar `verificar_ui.mjs` y
   `PROGRESO.md`. Restaura `frontend/package.json.md5` si cambió.
