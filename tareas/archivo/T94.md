1. Estado actual: ejecuta los modos `estados` y `reproductor` de
   `docs/investigacion/ui/verificar_ui.mjs` y guarda la lista exacta de comprobaciones
   fallidas (nombre, esperado, obtenido). Sirve como línea base.
2. Estado T89b: `git checkout <hash-T89b> -- frontend/src`, espera la recarga del dev

   `git checkout HEAD -- frontend/src` y comprueba que `git status --porcelain` queda
   limpio. Mismo script (el `.mjs` actual) en ambos estados.
3. Alterna al menos 2 pasadas por estado (actual / T89b / actual / T89b) para
   distinguir ruido de red (los proveedores devuelven contenido vivo).
4. Para cada fallo, clasifica:
   - **Entorno/datos**: idéntico con el código de T89b (p. ej. el proxy del
     contenedor ahora sirve el HLS y el reproductor ya no cae al iframe; el
     número de episodios o el contenido vivo cambia una medida).
   - **Regresión de código**: falla solo con el código actual.
   - **Expectativa obsoleta**: el modo comprueba algo que cambió a propósito.
5. Para los 4 fallos de `contain-intrinsic-size` en `estados`, reporta el valor
   obtenido frente al esperado y a qué ancho/estado ocurren; comprueba si dependen
   del anime o de los datos cargados (el proveedor puede devolver otra lista).
6. Para los 2 de `reproductor` (caso D), confirma si la fuente cargada es HLS por el
   proxy y por qué no cae al iframe; compara con el caso de T89b.
7. Informe en docs/investigacion/ui_regresiones_v1.5.md con una tabla
   `| modo | comprobación | actual | T89b | clasificación |` y la conclusión.
