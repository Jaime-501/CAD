# T67 — Restaurar el scroll del detalle cuando la lista se recarga

Contexto: v1.3.0, rama feature/episodios-incrementales. T66 separó la clave de scroll
por proveedor+slug. Falta el caso en que el detalle se recarga (stores de otro anime):
sincronizarVista hace scrollTo antes de que la lista exista y la posición se recorta a 0.
Solo frontend. Ningún Go.

Puedes tocar:
- frontend/src/VistaDetalle.svelte
- PROGRESO.md

NO debes tocar: *.go, frontend/wailsjs/**, api.ts, stores.ts, views.ts, ventana.ts,
revelar.ts, App.svelte, TarjetaEpisodio.svelte, wails.json, tareas/00_REGLAS.md.

## Comportamiento

1. En onMount, ANTES de decidir la rama: objetivo = recuperarScroll(claveScroll('detalle')).
2. Solo si objetivo > 0 Y la rama es la de recarga (openAnime), armar restauración
   pendiente. La rama de "vuelta con stores intactos" NO se toca (ya funciona).
3. Restauración: reactivamente cuando cambie episodios.length o episodesComplete, si hay
   restauración pendiente y document.documentElement.scrollHeight - window.innerHeight
   >= objetivo: window.scrollTo(0, objetivo) una sola vez y desarmar. Si episodesComplete
   es true y aún no alcanza: scrollTo al máximo posible y desarmar.
4. Cancelar (desarmar sin mover) ante wheel, touchstart, keydown o pointerdown del
   usuario, y en onDestroy. Los listeners se registran con { passive: true } solo mientras
   hay restauración pendiente y se limpian siempre (sin fugas).
5. Usar requestAnimationFrame antes de scrollTo para medir con el layout ya pintado.
6. No cambiar orden de la lista, episodioContinuar, animación de T65 ni la caché.

## Verificación (Playwright, localhost:34115)

1. JKAnime bleach: bajar a scrollY≈800 con la lista completa; abrir AnimeAV1 bleach
   (empieza en 0); volver a JKAnime bleach => la lista se recarga por lotes y el scroll
   acaba en ~800 cuando hay altura suficiente (anotar tiempo y scrollY final).
2. Mismo caso interrumpiendo: al volver, mover la rueda/teclado antes de que cargue =>
   NO se fuerza el scroll después.
3. Detalle -> reproductor -> "← Atrás" (stores intactos) sigue conservando el scroll.
4. Anime con pocos episodios y objetivo inalcanzable: acaba en el máximo, sin bucle ni error.
5. Primera apertura de un anime (objetivo 0): sin restauración, sin listeners activos.
6. Consola sin errores nuevos de nuestro código.
