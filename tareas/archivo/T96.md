# T96 — Diagnóstico del `pageerror` «Cannot read properties of null (reading 'nodes')»

## Objetivo

Averiguar de dónde sale el `pageerror` que aparece ya en el Home con el dev server y decidir
si **afecta al `.exe`** o es ruido del dev server. **Solo diagnóstico**: no se corrige nada.
Si resulta ser un bug de código, se abre una tarea de corrección aparte (T96b).

## Puedes tocar

- `docs/investigacion/pageerror_nodes.md` (informe nuevo).
- Scripts temporales **fuera del repo** (p. ej. en el directorio temporal del sistema).
- `PROGRESO.md` (tabla y pendiente).

## NO debes tocar

- Código de producto (`frontend/src/**`, `*.go`, `frontend/wailsjs/**`), `verificar_ui.mjs`,
  `a11y_auditoria.mjs`, datos guardados, `frontend/package.json.md5` (restaurar si cambia).

## Pasos

1. Estado inicial: `git status --porcelain` vacío. Documenta cualquier desviación.
2. **Reproducir y capturar la traza**: con un script Playwright temporal (fuera del repo),
   abre `localhost:34115`, escucha `pageerror` y `console`, y guarda `error.stack` completo,
   el momento (¿antes o después de `DOMContentLoaded`? ¿antes o después de que el Home pinte?)
   y cuántas veces ocurre. Repite 3 veces para ver si es determinista.
3. **Localizar el origen**: la traza apunta a un archivo. Averigua si es:
   a. código de la app (`frontend/src`), de SvelteKit/Vite, del cliente de Wails o del
      inyector del dev server (`/wails/ipc.js`, `/wails/runtime.js`, HMR);
   b. algo que solo existe en el dev server (HMR, `@vite/client`, wrapper de `wails dev`).
   Busca `nodes` con `grep`/`Select-String` en `frontend/src` y en el bundle de
   `frontend/dist` (tras `npm run build`) para ver si el patrón existe en el código de la app.
4. **Contrastar con la build de producción**: sirve `frontend/dist` con un servidor estático
   simple y repite el paso 2 (aviso: sin el puente `window.go` habrá un error distinto,
   `reading 'main'`; **no lo confundas** con el investigado: compáralos por mensaje exacto).
   Compara con el código de T89b (`git checkout 876d14c -- frontend/src`, restaurando después
   con `git checkout HEAD -- frontend/src`) para saber si es previo a la v1.5.
5. **Veredicto** (uno solo, justificado con evidencia):
   - **Ruido del dev server**: no existe en el bundle de producción ni en el código de la app.
   - **Afecta al `.exe`**: el origen está en código que va al bundle; indica archivo y línea.
   - **No concluyente**: qué falta y cómo se cerraría con el `.exe` (`-debug` + F12).
6. Escribe `docs/investigacion/pageerror_nodes.md`: método, traza (sin URLs firmadas ni
   tokens), comparación actual/T89b/producción, veredicto y propuesta (si aplica, ficha de T96b).

## Comprobación

- `git status --porcelain`: solo `docs/investigacion/pageerror_nodes.md` y `PROGRESO.md`.
- `git diff --stat -- '*.go' frontend/src frontend/wailsjs` vacío; `frontend/src` restaurado a HEAD.
- Log del script temporal sin errores ajenos al investigado (`ERR_EMPTY_RESPONSE`, etc.).
