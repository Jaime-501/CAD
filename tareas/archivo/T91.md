Añade, junto a las demás funciones, con comentario en español:
- `ventanaPantallaCompleta(activar: boolean): void` → llama a
  `WindowFullscreen()` o `WindowUnfullscreen()` dentro de try/catch; ante un

deben degradar sin romper nada.

### 2. pantallacompleta.ts (exporta exactamente esto)
```ts
export interface DocumentoConPantallaCompleta {
  fullscreenElement?: Element | null;
}
/** Elemento en pantalla completa del documento, o null si no hay ninguno. */
export function elementoEnPantallaCompleta(
  doc: DocumentoConPantallaCompleta
): Element | null;

export interface DependenciasVentana {
  esPantallaCompleta(): Promise<boolean>;
  entrar(): void;
  salir(): void;
}
export interface Sincronizador {
  /** Llamar en cada `fullscreenchange` con `activo = hay elemento en fullscreen`. */
  alCambiarDocumento(activo: boolean): Promise<void>;
  /** Síncrono. Restaura la ventana si fue este sincronizador quien la puso en fullscreen. */
  liberar(): void;
}
export function crearSincronizador(dep: DependenciasVentana): Sincronizador;
```
Reglas de `crearSincronizador`:
- Estado interno: `propia` (esta instancia puso la ventana en fullscreen) y
  `liberado`.
- Las llamadas a `alCambiarDocumento` se **serializan** en una cola de promesas
  (cada una espera a la anterior), así el orden de eventos se respeta aunque
  `esPantallaCompleta()` tarde.
- `activo = true`: si `propia`, no hace nada. Si no, consulta
  `esPantallaCompleta()`; si ya estaba en fullscreen, no hace nada y `propia`
  queda en false (la ventana se respeta al salir). Si no estaba, llama a
  `entrar()` y fija `propia = true`.
- `activo = false`: si `propia`, llama a `salir()` y `propia = false`; si no, nada.
- Tras `await esPantallaCompleta()`, comprobar `liberado` antes de llamar a
  `entrar()` (una operación en vuelo no debe entrar tras `liberar`).
- `liberar()`: `liberado = true`; si `propia`, llama a `salir()` y `propia = false`.
  Idempotente. Tras liberar, `alCambiarDocumento` no hace nada.
- Robustez: si `esPantallaCompleta()` rechaza, se trata como `false`. Si
  `entrar()` lanza, `propia` no se activa y la cola sigue viva. Si `salir()`
  lanza, `propia` queda en false igualmente. Ninguna entrada inválida lanza.

### 3. pantallacompleta.test.ts
Mismo patrón que `ventana.test.ts` (función `comprueba`, esbuild + node, cabecera
con el comando). Dobles con estado: la ventana falsa cambia su estado al llamar
a `entrar`/`salir`. Cubre como mínimo:
1. `elementoEnPantallaCompleta`: null, undefined, objeto y documento sin la propiedad.
2. Ventana normal: true → `esPantallaCompleta` 1 vez, `entrar` 1, `salir` 0; false → `salir` 1.
3. Ventana ya en fullscreen: true y false → `entrar` 0 y `salir` 0.
4. Dos `true` seguidos (cambio de elemento video→iframe): `entrar` 1 y consulta 1.
5. `false` sin haber entrado: nada.
6. `true` y `false` lanzados sin await entre ellos: orden entrar → salir y estado final fuera.
7. `false`/`true` rápidos tras haber entrado: salir → volver a entrar.
8. `liberar` con `propia`: `salir` 1 de forma síncrona; sin `propia`: nada; doble `liberar`: 1.
9. Tras `liberar`, `alCambiarDocumento(true)` no hace nada.
10. `liberar` con una consulta en vuelo (promesa controlada que se resuelve después): no se llama a `entrar`.
11. `esPantallaCompleta` rechaza → tratado como false y se entra.
12. `entrar` lanza → no rompe la cola; la siguiente llamada funciona.
13. `salir` lanza → `propia` queda en false.
